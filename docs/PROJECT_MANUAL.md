# PhenoChange website project manual

## Purpose

This document records the working architecture and maintenance conventions for the PhenoChange website.

PhenoChange is presented publicly as **a network for monitoring the phenology of forests and savannas**.

Public website:

https://kyledexter.github.io/PhenoChange/

## Platform

The website is a static Jekyll site hosted with GitHub Pages.

The repository is designed to remain straightforward to edit manually. Most public content is stored directly in Markdown pages rather than in a content-management system.

## Main pages

The following Markdown files live in the repository root:

- `index.md` — Home
- `about.md` — About
- `people.md` — People
- `institutions.md` — Partner Institutions
- `publications.md` — Publications
- `data.md` — Data
- `protocols.md` — Protocols
- `contact.md` — Contact

## Jekyll structure

- `_config.yml` — site configuration
- `_data/navigation.yml` — navigation menu
- `_includes/header.html` — header
- `_includes/footer.html` — footer and funding information
- `_layouts/default.html` — master layout
- `_layouts/page.html` — internal page layout
- `assets/css/style.css` — site-wide styling

The older YAML files for people, institutions and publications are no longer used. Those contents are maintained directly in the corresponding Markdown pages.

## Data-page architecture

The Data page is the most technically complex page.

### Site metadata

Authoritative file:

`assets/data/phenochange_site_metadata.csv`

It contains one row for each of the nine core sites, including:
- site name;
- country;
- vegetation type(s);
- mean latitude;
- mean longitude;
- elevation;
- MAT;
- MAP;
- number of active cameras, where included.

Site latitude and longitude are calculated as the mean coordinates of cameras with `Status = ON`.

MAT and MAP are derived from WorldClim v2.1 BIO1 and BIO12 using the 1970–2000 climatology at 2.5 arc-minute resolution.

Elevation values are based on field camera metadata. Kilwa uses a site mean of 140 m because camera-level elevation was unavailable.

The sortable table is generated by:

`assets/js/site_table.js`

Do not duplicate site metadata manually in `data.md`.

### Camera metadata

Authoritative active-camera file:

`assets/data/phenochange_active_cameras.csv`

This contains only cameras with `Status = ON` from the master PhenoChange camera spreadsheet.

The interactive map is generated by:

`assets/js/network_map.js`

The current map shows only the nine core PhenoChange sites.

### Map background and boundaries

The map uses:
- NASA Blue Marble Next Generation for the global raster background;
- Natural Earth for country boundaries;
- Leaflet for interactive mapping.

The map source credit should remain visible on the Data page.

### Camera interaction

Selecting a site displays its active cameras in a schematic radial arrangement. Camera positions in this diagram are deliberately schematic and do not represent true geographic spacing or orientation.

A future improvement is to draw these schematic camera nodes directly around the selected site marker on the map.

## Images

Current image folders include:

- `assets/images/people/`
- `assets/images/about/`
- `assets/images/home/`
- `assets/images/hero/`
- `assets/images/project/`
- `assets/images/protocols/`
- `assets/images/logos/`

Filename convention:
- lowercase where practical;
- underscores instead of spaces;
- avoid accented characters in filenames;
- `.jpg` for photographs where practical;
- retain `.png` or `.svg` where appropriate for logos.

People portraits use `.jpg` filenames and are referenced directly from `people.md` and `contact.md`.

When adding an image, update the relevant Markdown path rather than renaming existing assets casually.

## People

People are maintained directly in `people.md`.

Current categories:
- Coordinators
- Site Leaders
- PhenoChange Collaborators

Portraits are stored in:

`assets/images/people/`

The Contact page repeats the three coordinators with email links.

## Partner institutions

Institutions are maintained directly in `institutions.md`.

Ordering convention:
1. University of Turin
2. Universidade Estadual Paulista (UNESP)
3. Vale S.A.
4. remaining partners alphabetically

Institution logos are stored in:

`assets/images/logos/`

## Publications

Publications are maintained directly in `publications.md`.

Add new papers above older papers so the newest publication appears first.

When the accepted Methods in Ecology and Evolution paper is formally published, add it to Publications and replace the temporary notice on the Protocols page with the citation/link.

## Protocols

Downloadable documents are stored in:

`assets/documents/`

Current field-camera protocol:

`assets/documents/PhenoChange_Phenocam_Protocol_v1.pdf`

Downstream image-processing and analysis pipelines remain in development.

## Data access

The Data page currently states that a PhenoChange Data Sharing Agreement is being developed and directs enquiries to the three coordinators.

When the agreement is approved, add it to the website and update both the Data page and this manual.

## External links

Use `target="_blank"` and `rel="noopener"` for external links where HTML links are used.

For internal assets and pages, prefer Jekyll's `relative_url` filter so paths work correctly under the `/PhenoChange/` GitHub Pages base URL.

## Versioning and documentation

Maintenance documentation is stored in `docs/`:

- `PROJECT_MANUAL.md`
- `CHANGELOG.md`
- `ROADMAP.md`

The `docs/` directory is excluded from the generated public site.

After a substantial release:
1. update `CHANGELOG.md`;
2. move unfinished ideas into `ROADMAP.md`;
3. update `PROJECT_MANUAL.md` if architecture or maintenance procedures changed;
4. update root `README.md` if repository structure changed.

## Known current limitation

The camera expansion is rendered beneath the global map. This is functional but requires scrolling on many screens. The preferred future interaction is an in-map schematic expansion around the selected site centroid.

## Working principle

Keep the site simple enough that routine scientific-content updates can be made by editing Markdown and CSV files without rebuilding the website architecture.
